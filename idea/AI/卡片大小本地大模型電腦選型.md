# 卡片大小本地大模型電腦選型

更新日期：2026-09-20

## 先說結論

「卡片大小」和「能跑大模型」需要先定義：信用卡約為 85.6 × 54 mm，但開發板加上散熱、電源、儲存和外殼後通常都會超過這個尺寸。在這個體積內，實際合理的目標是本機執行 1–8B 參數的量化模型，而不是桌機等級的 30B、70B 模型。

推薦順序：

1. **Jetson Orin Nano Super 8GB**：7–8B、VLM、相機 AI 和成熟 GPU 生態的首選。
2. **Orange Pi 5 Pro 16GB**：尺寸最接近卡片、記憶體夠大，適合低成本 ARM 本機 LLM。
3. **Khadas Edge2 16GB**：更精緻緊湊的 RK3588S 選擇，官方提供 NPU LLM 安裝流程。
4. **Raspberry Pi 5 16GB**：最好上手、社群最大，但 LLM 主要靠 CPU，速度不是強項。
5. **LattePanda Mu 16GB**：需要 x86／Windows 軟體時選擇，但必須搭配 carrier board。
6. **LattePanda Mu Ultra 16GB**：體積小且 AI 能力高，但電源、散熱、carrier 與成本都更接近迷你 PC 專案。

## 快速比較

| Raspberry Pi 5 | 85 × 56 mm | 最高 16GB | VideoCore VII，無專用 LLM NPU | 1–3B 流暢度較合理；7–8B 可跑但偏慢 | 最容易買、教學與周邊最多 |
| Orange Pi 5 Pro | 89 × 56 mm | 最高 16GB LPDDR5 | RK3588S、6 TOPS NPU、Mali-G610 | 1.5–8B 量化 | 最像信用卡的完整高規 SBC |
| Khadas Edge2 | 約卡片級 | 最高 16GB | RK3588S、6 TOPS NPU | 官方支援 1.5B、2B-VL、6B、7B | 做工與官方 LLM 流程較完整 |
| Jetson Orin Nano Super dev kit | 約 100 × 79 mm 級，略大 | 8GB LPDDR5 | 1024 CUDA、32 Tensor、67 sparse TOPS | 官方定位最高約 8B | 本機 LLM／VLM 軟體生態最好 |
| LattePanda Mu | 69.6 × 60 mm 模組，不含 carrier | 8GB／16GB LPDDR5 | Intel N100／N305 iGPU，無 NPU | 1–7B CPU／iGPU 量化 | x86、Windows、Ubuntu 相容性 |

模型範圍不是硬性上限；context 長度、KV cache、量化方式、runtime 和是否將部分運算 offload 到 GPU／NPU 都會改變結果。「能載入」也不等於互動速度好用。

## 各選擇解析

### Jetson Orin Nano Super：最像真正的 Edge AI 電腦

官方規格為 8GB 128-bit LPDDR5、102 GB/s 記憶體頻寬、1024 CUDA cores、32 Tensor cores，Super 模式最高 67 sparse INT8 TOPS，功耗模式為 7–25W。NVIDIA 明確將它定位於可執行 Llama 3.1 8B 等最高約 8B 的 LLM、VLM 和 Vision Transformer。

優點：

- CUDA、TensorRT-LLM、Ollama、llama.cpp、Hugging Face 等生態成熟。
- 相機、影像、語音與 LLM 結合時最有優勢。
- 教學、範例與部署工具比多數 NPU SBC 完整。

限制：

- 8GB 是主要瓶頸；7–8B 必須使用量化，長 context 也會吃掉記憶體。
- developer kit 略大於信用卡，且高負載需要風扇與 25W 級電源。
- 若只做純文字小模型，硬體成本和功耗可能過高。

適合：離線語音助理、攝影機 VLM、機器人、多模態終端。

### Orange Pi 5 Pro 16GB：尺寸與能力最平衡

尺寸為 89 × 56 mm，接近信用卡；採 RK3588S，四核 Cortex-A76 加四核 Cortex-A55、Mali-G610 GPU、最高 6 TOPS NPU，提供最高 16GB LPDDR5、M.2 NVMe、Wi-Fi 5 和 Bluetooth 5。

優點：

- 16GB 記憶體比 8GB Jetson 更能容納模型與較長 context。
- 完整 SBC 的尺寸非常接近卡片。
- 有 NVMe、網路、GPIO 和顯示輸出，適合做成獨立裝置。

限制：

- Rockchip NPU 需要 RKLLM／RKNN 相容模型與轉換流程，通用性不如 CUDA。
- 不受 NPU 支援的模型可能回到 CPU／GPU，實際速度落差很大。
- 官方系統、kernel 與社群整合通常不如 Raspberry Pi 一致。

適合：成本敏感的離線文字助理、家庭 AI gateway、資訊終端。

### Khadas Edge2 16GB：精緻的 RK3588S 平台

同樣採 RK3588S 與 6 TOPS NPU。Khadas 官方提供 `khadas_llm.sh`，可安裝和啟動 NPU 優化的 DeepSeek 1.5B／7B、Qwen2 2B-VL、ChatGLM3 6B 等模型。

優點：

- 官方已整理 LLM-on-NPU 的快速流程，試驗成本較低。
- 板上有 Wi-Fi／Bluetooth、雙麥克風、多組 camera、顯示和 fan header。
- 適合語音或視覺裝置。

限制：

- 仍受 Rockchip 專用 runtime、模型格式與算子支援限制。
- 相較 Orange Pi 通常較偏精品開發板，選購前需評估價格與供貨。

適合：希望快速試 RK3588 NPU、語音介面、相機 VLM prototype。

### Raspberry Pi 5 16GB：最安全的入門選擇

85 × 56 mm，搭載四核 Cortex-A76 2.4GHz、最高 16GB LPDDR4X、PCIe 2.0 x1，可經 HAT 加 NVMe。官方建議高效能使用時配主動散熱與 5V/5A、27W USB-C 電源。

優點：

- 文件、社群、外殼、相機、HAT 和軟體支援最好。
- 16GB 能容納較大 Q4 模型，安裝 Ollama／llama.cpp 容易。
- 適合先證明產品體驗，再換更專門的 AI 硬體。

限制：

- 沒有專用 NPU，LLM 主要靠 CPU；能載入 7–8B 不代表回覆速度舒適。
- 加風扇、NVMe HAT 後厚度和面積不再像裸卡片。

適合：第一次做本機 LLM、對速度要求不高的桌面助理、軟體 prototype。

### LattePanda Mu 16GB：需要 x86 時

69.6 × 60 mm 的 compute module，提供 Intel N100 或 N305、最高 16GB LPDDR5 和 64GB eMMC，可執行 Windows 10／11 或 Ubuntu。它本身不是完整 SBC，需要 Mini／Lite carrier 或自行設計 carrier。

優點：

- x86 相容性好，較容易執行只提供桌面 Linux／Windows build 的工具。
- N305 為 8 核，CPU 推論能力比許多 ARM SBC 強。
- PCIe、SATA、USB 和顯示擴充彈性大。

限制：

- 沒有 NPU，內顯也不是為大型生成式 AI 設計。
- 模組雖小，加 carrier、SSD、電源和散熱後會明顯變大。
- 可設定功耗範圍高，portable device 的電池與散熱設計比較難。

適合：需要 Windows、x86 套件、瀏覽器自動化或一般迷你 PC 功能的 AI 終端。

### LattePanda Mu Ultra：高階卡片模組

模組同樣為 69.6 × 60 mm，採 Intel Core Ultra 5 226V 或 Ultra 7 256V，16GB LPDDR5X；官方資料列出 40／47 TOPS NPU，整體峰值 97／115 INT8 TOPS。

它的 CPU、Arc GPU 和 NPU 明顯更強，但需要 50W+ 電源預算、carrier、PCIe 儲存及完善散熱。適合客製化高階終端，不適合把「卡片大小」理解為完整無風扇掌上裝置。

## 記憶體與模型大小的簡化估算

只看 Q4 權重，可粗略估計每 10 億參數約需 0.5–0.7GB；實際還要加 runtime、KV cache、圖形記憶體共享、context 和作業系統：

- 1–3B Q4：4–8GB 裝置可以實用嘗試。
- 7–8B Q4：8GB 是勉強下限，12–16GB 比較安心。
- 13–14B Q4：最好 16GB 以上，但卡片級裝置的速度通常不理想。
- 30B 以上：不建議以這類卡片電腦為目標。

若要跑 VLM，還要為 vision encoder、輸入影像和額外 cache 保留空間。

## 依用途選擇

### 純文字離線助理

- 預算與尺寸優先：Orange Pi 5 Pro 16GB。
- 安裝簡單優先：Raspberry Pi 5 16GB。
- 推論生態與速度優先：Jetson Orin Nano Super。

### 語音助理

- Jetson Orin Nano Super：ASR、LLM、TTS 串接較有餘裕。
- Khadas Edge2：板載麥克風與 NPU，適合做緊湊 prototype。

### 相機與 VLM

- 首選 Jetson Orin Nano Super。
- 次選 Khadas Edge2／Orange Pi 5 Pro，但需先確認目標 VLM 能否使用 RKNN／RKLLM。

### Windows 或既有 x86 軟體

- LattePanda Mu 16GB；若真的需要較強 AI NPU／GPU，再看 Mu Ultra。

### 電池掌上裝置

這些 SBC 都不是理想的全天候掌上 LLM。除了板子，還需要電池、BMS、DC-DC、螢幕、散熱與安全外殼。若要像 Cardputer 一樣可攜，較合理的架構可能是：

- 掌上裝置只負責輸入、顯示與喚醒詞。
- LLM 放在口袋中的較大運算盒、家中 edge server，或需要時使用雲端。
- 離線時改跑 0.5–3B 小模型，而不是強求 8B。

## 我的具體建議

如果現在要買一塊開始做：

- **想做相機／語音／機器人，選 Jetson Orin Nano Super。**
- **想要真正接近信用卡、16GB 且成本較合理，選 Orange Pi 5 Pro 16GB。**
- **完全是第一次做，先選 Raspberry Pi 5 16GB，接受它比較慢。**
- **必須跑 Windows，選 LattePanda Mu 16GB + Mini Carrier。**

第一個測試模型可從 Qwen 2.5／3 系列的 1.5B–3B instruct 量化版開始，再測 7–8B；先量測首 token 延遲、每秒 token、記憶體、功耗與表面溫度，再決定硬體是否適合產品化。

## 掌上型、電池供電、小模型方案

若模型可以縮小到 0.3–1.5B，最佳方向會從高性能 AI 板改成低功耗的 Zero-form-factor SBC。

### 首選：Radxa ZERO 3W 8GB

- 尺寸只有 65 × 30 mm。
- RK3566，四核 Cortex-A55 1.6GHz。
- 最高 8GB LPDDR4。
- Wi-Fi 6、Bluetooth 5.4、USB-C、micro HDMI、microSD，並可選 eMMC。
- 5V／2A 供電規格，實際設計應依峰值電流保留餘裕。

它沒有專門跑 LLM 的 NPU，但 8GB RAM 對掌上裝置非常有用：可以使用 llama.cpp 類 CPU runtime 執行 0.5B、0.6B、1B 或 1.5B 的 Q4 模型，同時仍保留空間給 Linux、UI 和 KV cache。CPU 速度不會像手機旗艦晶片，但適合短問答、指令解析、筆記整理與離線工具。

這是目前最符合「真正掌上型＋電池＋本機小模型」的選擇。

### 次選：Orange Pi Zero 3 4GB

- 85 × 56 mm，約信用卡大小。
- H618，四核 Cortex-A53 1.5GHz。
- 最高 4GB LPDDR4。
- Wi-Fi 5、Bluetooth 5、USB-C、micro HDMI。

4GB 適合 0.3–1B Q4；1.5B 能否保持足夠 context 和流暢 UI，需要實測。板子比 Radxa ZERO 3W 大、CPU 架構較舊，但通常容易取得且接口完整。

### 不建議：Raspberry Pi Zero 2 W

雖然尺寸同為 65 × 30 mm、低負載功耗也很漂亮，但只有 512MB RAM。它適合當輸入／顯示終端、語音喚醒器或雲端模型 client，不適合執行現代文字 LLM。若強行使用極小模型，作業系統和 runtime 留下的空間會太少。

## 適合掌上型的模型級別

可優先測試以下級別，而不是直接追 7B：

- **約 0.3–0.6B**：反應最快，適合分類、指令轉換、短句改寫和固定領域問答。
- **約 1B**：語言能力和速度較平衡，適合離線筆記、簡短助理與對話介面。
- **約 1.5B**：品質通常更好，但首 token 延遲、發熱和電池消耗會明顯增加。
- **3B**：在 8GB 記憶體中可能載入，但對 RK3566 掌上裝置通常太慢，不應作為第一版目標。

可從 Qwen 0.6B／1.5B、Llama 3.2 1B、SmolLM 360M／1.7B 等家族的 GGUF Q4 版本開始比較。模型選擇需依中文能力、授權、context 與工具呼叫需求重新確認。

## 掌上裝置建議架構

```text
Radxa ZERO 3W 8GB
├─ 3.5–5 吋低功耗 IPS 或電子紙
├─ 小鍵盤／CardKB／旋鈕＋按鍵
├─ 單節 LiPo 或 18650 電池
├─ 具 power-path 的充電與 5V boost 模組
├─ 實體電源開關與安全關機機制
├─ 小型散熱片
└─ microSD 或 eMMC 儲存模型
```

軟體可使用精簡 Debian／Radxa OS、llama.cpp server 和非常輕量的本機 Web UI。不要安裝完整桌面環境；直接開 kiosk browser、SDL framebuffer 或簡單 native UI，可以省下記憶體和開機時間。

## 適合的產品方向

- **離線 Idea Collector**：鍵盤輸入一句點子，小模型協助命名、分類和補上標籤，之後再同步 GitHub。
- **離線寫作工具**：改寫短句、摘要本機筆記、產生提綱。
- **自然語言遙控器**：把一句命令解析成控制 Home Assistant、機器人或感測器的結構化指令。
- **口袋知識庫**：只針對一小套文件做搜尋與短回答；retrieval 在本機完成。
- **隱私日記**：資料與模型完全留在裝置，連網只做使用者明確啟動的備份。

## 電池與體積判斷

板子小不代表整機一定小。最大的空間通常來自電池、螢幕和鍵盤。續航不能只看 SBC 的平均功耗，還需把螢幕背光、Wi-Fi、儲存和 DC-DC 效率算入：

```text
預估續航（小時）≈ 電池 Wh × 轉換效率 ÷ 整機平均 W
```

第一版建議先使用 USB 行動電源或有完整保護的現成 UPS 模組量測整機功耗，再決定電芯容量。不要讓 Linux SBC 直接切斷電源；加入 shutdown 按鍵、低電量通知和檔案系統保護，避免損壞 microSD。

## 更新後的具體推薦

依「掌上型、電池供電、模型可以小」這個條件：

1. **買 Radxa ZERO 3W 8GB，先跑 0.6B 或 1B Q4。**
2. 使用 3.5–4 吋螢幕和最簡輸入，先做無電池的桌上 prototype。
3. 量測模型生成時的峰值電流、溫度和 token 速度。
4. 確認體驗可接受後，再加入 LiPo／18650、充電與外殼。
5. 若速度不足，不急著換 7B 板子；先縮短 context、使用更小模型、限制輸出長度並將固定工作改成規則程式。

## 掌上型 prototype 價格估算

價格快照：2026-09-20。匯率以約 `US$1 ≈ NT$31.8` 粗估；實際台灣售價會受到庫存、運費、稅和版本影響。

### Radxa ZERO 3W 主板

- 官方合作通路顯示全系列從約 **US$32.90** 起，但這是低記憶體版本。
- 8GB／無 eMMC 版本可先抓約 **US$55–70**，約 **NT$1,750–2,250**。
- 8GB／64GB eMMC 版本的通路紀錄約 **US$55–80**，約 **NT$1,750–2,550**；缺貨或轉售時可能更高。
- 專用散熱片官方通路約 **US$2.99**，未含運費。

### 完整掌上 prototype

| 項目 | 粗估價格（NT$） |
| --- | ---: |
| Radxa ZERO 3W 8GB | 1,750–2,550 |
| 32–128GB microSD；有 eMMC 時可先省略 | 250–600 |
| 3.5–4 吋 IPS 螢幕 | 600–1,300 |
| 小鍵盤／CardKB／自製按鍵板 | 300–900 |
| LiPo／18650 電池與安全電池座 | 300–700 |
| 充電、power-path、5V boost | 300–800 |
| 散熱片、線材、開關與接頭 | 200–500 |
| 3D 列印外殼 | 200–800 |

因此：

- **最小桌上驗證版**：主板、記憶卡、散熱與既有螢幕／鍵盤，約 **NT$2,300–3,500**。
- **完整掌上 prototype**：約 **NT$4,000–7,000**。
- 若使用高品質電源板、客製鍵盤和更好的螢幕，預算可能超過 **NT$8,000**。

成本控制上，第一階段建議買 **8GB 無 eMMC** 版本加可靠 microSD，先用現成 USB 行動電源和外接螢幕測試模型。確定速度值得做成掌上裝置後，再購買螢幕、電池與客製外殼，避免一次買齊後才發現推論速度不合需求。
